## Patch history

Every code change is marked with `// WONKY PATCH <id>`. Tests of the patches are in
`test/textmate/wonky_patches_test.dart`: every embedded grammar highlights a realistic sample
and every prefix of it (half-typed code), and the patched grammars scope their key tokens.

The ids and descriptions below are the history from the vendored package. File paths refer to
`third_party/syntax_highlight` at the time; their current homes are listed above.

## SH-1 — Drop `CodeEditor` and `super_clipboard`

- **Reason**: `CodeEditor` (a standalone editor widget) is unused by Wonky Write and is the only
  user of `super_clipboard`, a large native/web plugin.
- **Changes**: `lib/src/code_editor.dart` deleted; `super_clipboard` removed from `pubspec.yaml`.
- **Files**: `lib/syntax_highlight.dart`, `pubspec.yaml`
- **Upstream**: not upstreamable as is (could become a separate library entry point).

## SH-2 — Case-insensitive `(?i)` regexes

- **Reason**: TextMate grammars use Oniguruma's inline `(?i)` flag, which Dart's `RegExp` does
  not support, so e.g. no SQL keyword (`SELECT`, `FROM`, …) was ever highlighted.
- **Fix**: a leading `(?i)` is stripped and the regex is built with `caseSensitive: false`.
- **Files**: `lib/src/span_parser.dart`
- **Upstream**: generally applicable; to be proposed.

## SH-3 — Rewritten Swift, TypeScript, JavaScript, Python and Rust grammars

- **Reason**: the bundled grammars were too broken to use: Swift and TypeScript had a
  `meta.declaration` rule that swallowed the rest of the line (strings, keywords and types lost
  their colors); JavaScript highlighted regex literals as division operators; Python had no
  `import`/`from`, decorators, f-strings or builtins; Rust read lifetimes (`'a`) as character
  literals, coloring everything up to the next quote as a string.
- **Fix**: the five grammars are generated by `tool/gen_grammars.py` (flat rule lists; scope names
  the bundled VS Code themes color). The parser has no `$self` includes, so each grammar's top
  level lives in the `#main` repository rule. Regenerate with
  `python3 tool/gen_grammars.py grammars`.
- **Files**: `grammars/{swift,typescript,javascript,python,rust}.json`, `tool/gen_grammars.py`
- **Upstream**: to be proposed.

## SH-4 — Scope-level API

- **Reason**: Wonky Write colors code with its theme's syntax palette (Write 06 §2.5), not with a
  VS Code `HighlighterTheme`, so it needs the TextMate scopes of each span rather than a styled
  `TextSpan`; it also loads grammars lazily and must know which are loaded.
- **Changes**: `Highlighter.isInitialized(language)` and `Highlighter.parseScopes(language, code)`
  (sorted, disjoint `ScopeSpan`s, scopes outermost first); `ScopeSpan` is exported.
- **Files**: `lib/src/highlighter.dart`, `lib/syntax_highlight.dart`
- **Upstream**: generally useful; to be proposed.

## SH-5 — Grammar fixes: JSON numbers, CSS `@media`, Go `package`/`import`

- **Reason**: found while checking every language in the Write editor. The JSON `number` regex
  still contained the line breaks of its original extended-mode (`(?x)`) source, so no number
  ever matched (they were scoped `invalid.illegal`); `@media` and Go's `package`/`import`
  keywords had no scope of their own (only the enclosing `meta.*` region), so they stayed
  uncolored.
- **Fix**: the JSON number regex is written on one line; CSS `@media` and Go `package`/`import`
  get `beginCaptures` with `keyword.*` scopes (the media `{` is
  `punctuation.definition.block.begin.css`).
- **Files**: `grammars/json.json`, `grammars/css.json`, `grammars/go.json`
- **Upstream**: to be proposed.


## SH-6 — Next-match search, own scanner (performance; Slides SL-26)

Made in `wonky_code` (not in the vendored package), for the 07 §14 tokenizer budget (1,000
lines of Dart ≤ 15 ms desktop / ≤ 30 ms web). It was ≈ 56 ms on the Dart VM; ≈ 17 ms after the
patch (VM JIT and AOT, on a loaded 12-core laptop).

- **Reason**: the engine tries every rule at every character and advances one character when
  none matches; `string_scanner`'s `LineScanner` recounts newlines with a regex on every
  position change and from the string start whenever a scanner is created at a position; capture
  patterns were re-parsed (regexes recompiled) on every match.
- **Changes** (`lib/src/textmate/span_parser.dart`, all marked `WONKY PATCH SH-6`):
  - the top-level loop and `_scanUpToEndMatch` jump to the leftmost position where the rule
    list (or the `end` pattern, which wins ties) can match: the leaf regexes of a rule list
    (simple `match`, multi-line `begin`, through `patterns` and `include`s) are searched with
    `allMatches(string, from)`; a leftmost search finds exactly the first position where
    `matchAsPrefix` succeeds, so the spans are unchanged. Results are memoized per scanner and
    regex ("the next match at or after `from` is `at`" holds for every later `from'` ≤ `at`),
    and a per-rule-list min-heap of the leaves' next positions answers without visiting every
    leaf; a memo also lets `scan` skip rules proven not to match at the current position;
  - the engine's own `LineScanner` (same API subset) computes line/column on demand from a
    newline index shared with scanners over a prefix of its string; `location` is lazy;
  - capture `patterns` are parsed once per capture map; the `while`-rule line regex is
    compiled once.
- **Verification**: spans identical to the unpatched engine for every grammar sample, every
  prefix of it, 200 random mutations of it and a 40× repetition (6,068 texts, compared before
  the change); `test/perf/budgets_test.dart` (`dart test -P slow`) measures the budget.
- `string_scanner` is no longer imported by the engine and was removed from the dependencies (SL-23).
- **Upstream**: generally useful; to be proposed with the pure-Dart split (Q26).


## SH-7 — Capture offsets (correctness; Slides SL-35)

Made in `wonky_code` while switching Write's exports to the shared tokenizer (SL-35).

- **Reason**: Dart's `Match` has no group offsets, and the engine placed every capture at the
  first occurrence of its text in the whole match (`match.indexOf(captureText)`). A capture
  whose text also occurs earlier was scoped in the wrong place: in `function f`, `def f`,
  `func f`, `fn f` (JavaScript, TypeScript, Python, Swift, Rust; also `class A: B`-style type
  names) the name scope landed on the keyword's first letter. The tokens then overlapped
  (breaking the `CodeTokenizer` contract), the real name stayed plain in the editor and Slides,
  and Write's HTML export would have written `functionfunction f`.
- **Changes** (`lib/src/textmate/span_parser.dart`, `_CaptureOffsets`, marked
  `WONKY PATCH SH-7`): the regex source is read once per `RegExp` into its group tree (escapes,
  character classes, non-capturing groups and lookarounds skipped; `(?<name>` captures). Groups
  are numbered by their opening parenthesis, so a group starts at or after its parent and
  after the end of its previous matched sibling, and ends inside its parent; each capture is
  searched from there. When the tree doesn't match `groupCount`, or a capture lies outside its
  parent (lookarounds), the old search is used. It is still a search: a capture whose text
  also occurs in an uncaptured gap before it, or a quantified group (which holds its last
  iteration), can still be misplaced. `TextMateTokenizer` therefore also clips a token that
  would overlap the previous one, so the contract holds in every case.
- **Verification**: spans compared with the SH-6 engine over every grammar sample, every
  prefix of it, 200 random mutations of it, a 10× repetition and extra snippets (6,094 texts):
  13 texts changed (JavaScript 2, Python 3, Rust 1, Swift 4, TypeScript 3) — exactly the 13
  that had overlapping spans before, none after; every change moves an `entity.name.function`
  / `entity.name.type` span from the keyword to the name. Tests:
  `test/textmate/textmate_tokenizer_test.dart` ("Given a name whose text also occurs earlier
  in its match"). Budget (`dart test -P slow`): 1,000 lines of Dart ≈ 19 ms, unchanged within
  noise.
- **Upstream**: a bug fix; to be proposed with the pure-Dart split (Q26).
